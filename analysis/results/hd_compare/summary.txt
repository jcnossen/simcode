# Reading:
# - DECODE (6-frame sums, trained on the same vectorial PSF) is the strongest pattern-free baseline: recall 0.77 / 0.83, close to
#   ours p1 (0.81 / 0.88), 6-13x SIMCODE's filtered output. Its per-target precision is the issue: RMS/CRLB 1.5-1.8x ours p2 at 700-4000
#   (paired 200-2000: 3.85 vs 2.29 at 20 nM, 2.82 vs 1.88 at 2.5 nM), gross 12.7 / 5.6 % vs 2.65 / 1.43 %, and its confident outputs
#   include FPs (recall at <= 1 % FP 0.03 / 0.07 vs 0.76 / 0.90). Its sigmas are close to calibrated (zcal 1.1-1.2).
# - Per-frame DECODE + linking: higher recall (0.84 / 0.89) but 23-26 % FP and worse precision than the summed model.
# - Sub-pixel pairs: DECODE merges as often as ours (d <= 1 px: 40-43 % merged); it does not resolve what ours misses.
# - FRC: DECODE beats ours on top-N FRC (m20qh N 26k / 49.7k: 11.7 / 12.9 vs p2 13.4 / 14.1; m25qh N 38k: 11.6 vs 13.7) and on
#   m25qh even at the full common N 212.9k (16.0 vs 17.1 nm), while on the SAME rows it is less accurate vs GT
#   (topn_frc_check_<m>.txt: m20qh N 26k 8.6 vs 6.4 nm/axis RMS, gross 0.44 vs 0.01 %; m25qh N 212.9k 17.5 vs 12.6 nm/axis,
#   gross 5.7 vs 1.7 %; static (per-event) and window-to-window error both larger). Cause (adjcorr_check_<m>.txt): the FRC halves are
#   alternating disjoint windows, and DECODE's 3-sum input makes adjacent windows share data: error correlation between window w and
#   w+6 of the same event is +0.66-0.70 for DECODE (SIMCODE +0.58-0.64, whose network also sees neighbouring frames) vs +0.30-0.38 for
#   ours p1/p2 (per-window input; the residual is per-event static error) and +0.23-0.28 for per-frame DECODE + linking. Correlated
#   errors land in both halves and raise the FRC without better accuracy. Its top-N sets also hold fewer events with more windows each
#   (5.5 vs 4.7 rows / event at m20qh N 26k). -> Between-window FRC is not a valid cross-method precision measure for methods with
#   temporal context; use the GT metrics (sim) or a split that does not share input frames across halves (e.g. halves = alternating
#   blocks of >= 3 windows). Random-N FRC at small N: ours p2 < DECODE (31.9 vs 43.4 at m20qh 49.7k; 25.7 vs 27.8 at m25qh 38k).
# - SMLM tuned: the chi^2 filter cleans the output (FP fraction 0.066 -> 0.024 at 20 nM; recall at <= 1 % FP 0.007 -> 0.042 and
#   0.018 -> 0.17 at 2.5 nM; gross 36 -> 26 %) but recall stays at 0.06 / 0.19: the classical detection merges neighbours. The
#   conclusion that classical fitting fails at these densities does not depend on the paper settings.
# - Grid fairness (critic 35 #1): every FRC here is on a common window-start grid for all methods (A: starts % 6 == 0); grid B
#   (starts % 6 == 3) reproduces grid A (median |A - B| 0.5 / 0.3 nm, max 2.3 nm at N >= 26k; up to 10 nm at N 4.4k, m25qh). The SIMCODE-vs-ours random-N gap (16.6 vs
#   31.9 nm at 20 nM) is therefore not a grid artefact in this sim protocol; it is SIMCODE's selection (see topn). The real-data
#   frc_matched.py comparison (critic 35 #1) is NOT redone here (no real-data processing in this task).
